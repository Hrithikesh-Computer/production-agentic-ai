# Context Lifecycle Decision

Defer a context-lifecycle prototype. Documents 03 and 04 describe multi-step, tool-using workflows, but both remain design-only with no executable context stream, state store, or retention policy to test; the CRM prototype from Action 2 currently handles one customer-ID request at a time and retains no cross-turn state, so the lifecycle model is not a prerequisite for its current behavior. The context-engineering article itself frames lifecycle management as most valuable for long-running, multi-step agents, but this repository does not yet provide an implemented workflow or representative context data from which to choose and verify a meaningful classification/scoring slice. Revisit when the CRM prototype gains multi-turn sessions or another agent workflow is implemented with persistent context; then select one context stream, define retention and deletion rules with an owner, and test classify/score behavior against that workflow. Until then, a prototype would encode unsupported policy assumptions.
