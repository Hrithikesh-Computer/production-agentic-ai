# D11 Risk Row: Audit Temporal Ordering

- **ID:** D11
- **Statement:** For every persisted `approval_approved` event $E$ associated with approval $A$, require $E.event\_ts \ge A.created\_at$. The prior implementation used an unbounded service clock for the approval transition and audit event. A separate monotonic transition-order token would be a stronger contract; it is not implemented or verified by this repair.
- **Scope:** Review timestamp source → `ApprovalsStore.set_review()` → `AuditStore.write()` → audit ordering/reconciliation.
- **Likelihood:** **VERIFIED-IN-THIS-ENVIRONMENT:** the previous shared review path failed the regression with service clock `90` and `created_at=100`; after repair, both current and fixed variants persist `approved_at=100` and `event_ts=100` in the same condition. The regression and the final `durability-20261009-repair-03` campaign are recorded in [tests/test_audit_temporal_ordering.py](tests/test_audit_temporal_ordering.py) and the local [fault-injection results](artifacts/fault-injection-approval-audit.csv). This is a controlled two-variant test, **not** an operational likelihood estimate. **UNKNOWN-WITH-RESOLVING-QUESTION:** production clock skew magnitude/rate and any requirement for a monotonic transition token remain unknown.
- **Impact:** **INFERENCE, medium-to-high:** audit chronology/provenance and incident reconstruction can be wrong or ambiguous. This is an **audit-quality failure**, not evidence that an unauthorized reviewer was accepted or that the CRM authorization decision changed. If regulated evidence requires trusted ordering, compliance exposure may be high; applicable requirement is **UNKNOWN** pending audit/control mapping.
- **Detection:** The service-level clock rollback is normalized before persistence and checked by [test_audit_temporal_ordering.py](tests/test_audit_temporal_ordering.py). A separate injected writer that changes the event timestamp after normalization still persists `event_ts=90 < created_at=100`; the harness detects this only by reading the persisted event and comparing it with the approval. No runtime monitor or production alert for downstream writer corruption is evidenced.
- **Reversibility:** Before audit export, a correction/annotation can preserve the original value and append a corrected ordering record. After external use, the original chronology cannot be made true retroactively; only correction and provenance can be appended. **INFERENCE.**
- **Priority:** **High, conditional on audit chronology being a control requirement; medium confidence.** The pre-repair current path reproduced the lower-bound violation while the prior fixed wrapper bounded that service-clock case; the repaired shared service passes in both variants. Deployment frequency and required time semantics remain UNKNOWN.
- **Mitigation:** The repair floors review transition/audit timestamps at `approval.created_at` in `CRMExecutionService.review()` and tests both local variants. Remaining work, if required by the control contract: persist a monotonic per-approval/per-tenant ordering token, reject or detect post-normalization audit-writer mutation, and test external clock/time-source and concurrent ordering behavior.
- **Owner role:** Audit owner (control), security (trust model), engineering/platform (write-time validation), operations (clock monitoring).
- **Evidence:** `AuditEvent.event_ts` is persisted by the audit store at [audit_store.py](prototypes/crm_operational_copilot/audit_store.py); review now floors the service clock against `approval.created_at` at [execution_service.py](prototypes/crm_operational_copilot/execution_service.py); the fixture uses `created_at=100` in [test_crm_validation_scenarios.py](tests/test_crm_validation_scenarios.py). Final regression result: two passing parametrizations; final relevant contract run: `20 passed, 8 xfailed`. The separate writer-backdating injection remains fail-silent and is precisely classified in [EVIDENCE.md](EVIDENCE.md).

**Evidence tier:** VERIFIED-IN-THIS-ENVIRONMENT for the created-at lower-bound under the tested local service-clock skew; INFERENCE for business impact and priority; UNKNOWN-WITH-RESOLVING-QUESTION for production clock behavior, monotonic ordering requirements, and compliance applicability. Downstream audit-writer integrity and deployment behavior are not verified.
